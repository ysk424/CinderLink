# CinderLink 1.0.1 の使い方

CinderLink は、UE Editor 内で公式 Codex を利用する非公式プラグインです。
1.0.0 では Python 制作モードを追加しました。材質・照明・配置などを調査し、
Python を実行し、結果を確認して修正する作業を、開いている Editor 内で進められます。

## 起動とモード

1. UE 5.8 で対象プロジェクトを開き、Window → CinderLink を開きます。
2. 自動接続が Ready になるまで待ちます。Codex のログインは事前に `codex login` で行います。
3. 通常のファイル変更と UE 操作のチェックは従来どおり有効です。
4. Python を使うときは **Enable Python authoring (Unreal host permissions)** を有効にします。
   ファイル変更・UE 操作の両方も有効である必要があります。
5. Python 制作モードは続けて使えます。解除、切断、新しいスレッド、Stop turn、
   またはファイル変更・UE 操作の許可を外すと解除されます。モードの再有効化はターン終了後に行います。

Python 制作モードは初期状態では無効です。有効中は画面上部に表示されます。
有効化は **UE Editor の権限で任意 Python を実行する選択**です。Codex の通常コマンドに
適用するプロジェクト限定のファイル制限は、UE 内の Python には適用されません。
Python はプロジェクト外のファイルや通信にもアクセスできるため、通常モードと同じ
隔離があるとは扱いません。画面のファイル変更チェックを外しても、既に実行された
Python の処理や副作用を巻き戻すものではありません。

スクリプトは短い単位で実行します。実行中は Editor の画面操作が止まることがあります。
Stop turn は後続の要求を停止するもので、実行中の Python や UE の処理を強制中断する
機能ではありません。長いループ、常駐処理、バックグラウンド処理、起動時スクリプトは使いません。
実行ツールは PIE／Simulate の実行中・開始待ちには動きません。

## モデルと推論量の確認

1.0.1 ではパネル上部に **Model: gpt-6-astra | Reasoning: xhigh** のように表示します。
モデル名と推論量は、接続先の Codex がそのスレッドについて返した値です。
モデルを固定したり、別の Codex 画面の選択を取り込んだりする機能ではありません。
`/model` や `/status` を入力しなくても確認できます。スラッシュコマンド自体は未対応です。

接続前は `--`、Codex が値を返さない項目は `not reported` と表示します。
切断・再接続・新しいスレッドでは以前の値を消し、取得できた値に更新します。
Codex が実行中のモデル切り替えを通知した場合は、該当ターンのモデルを別の行に表示します。
その通知には推論量がないため、元のモデルの推論量を転用しません。

## 最初の指示の例

> Python 制作モードで作業します。まず現在のレベルと材質を調べてください。
> 元の風景を保管し、試作用マップと試作用マテリアルを作って比較します。
> 変更する素材のフォルダーをバックアップ対象に指定し、短いスクリプトで進めてください。
> 保存した素材名と変更内容を日本語で説明し、採用した処理を再利用できるスクリプトに残してください。
> 個人情報・機器・通信にはアクセスしないでください。

Git リポジトリと UE プロジェクトのルートが異なる場合、Codex の通常ファイル操作は
`.uproject` のあるフォルダー以下です。必要な制作指示はその範囲に置いてください。
Arrietty-row なら Python 用の素材調整だけを試作用フォルダーで行い、水面 Z=0、遠景、
ケルビン波・白波・操作系を維持することを指示します。

## 追加された操作

| 操作 | 用途 |
| --- | --- |
| `ue_python_status` | Python の準備状態と、そのターンの制作モードを確認 |
| `ue_python_execute` | コード保存・指定フォルダーのバックアップ後に実行。出力、エラー、保存済みファイルの差分を返す |
| `ue_python_get_run` | 実行 ID から過去の結果と復元情報を読む |
| `ue_python_save_recipe` | 実行済みコードを `Scripts/CinderLink/<名前>.py` に保存。既存ファイルは上書きしない |

`ue_python_execute` には `label`、`code`、`backup_paths` を渡します。
`backup_paths` は `/Game/Row/Lookdev` のような Content 内のディレクトリ名の配列です。
読み取りだけの場合は `[]` を明示します。これはバックアップ範囲の申告であり、
Python のアクセス先を制限する仕組みではありません。

各実行は `Saved/CinderLink/Python/<実行ID>/` に保存されます。

- `script.py`: 実行するコード。実行前に UTF-8 で保存します。
- `result.json`: 実行状態、出力・例外、経過時間、バックアップ一覧、ディスク上の差分。
- `backup/Content/...`: 指定フォルダーの変更前ファイル。

保存済みファイルのバックアップは実行あたり最大 1 GiB・10,000 ファイルです。
バックアップ対象に未保存の UE パッケージがある場合は実行を止めます。保存するか変更を
戻してから再実行してください。バックアップできない場合は Python を実行しません。
最初は小さい試作用フォルダーを使うのがおすすめです。

バックアップは指定したフォルダーの **ディスク上のファイル**です。
別フォルダーの共有材質、World Partition の `__ExternalActors__`・`__ExternalObjects__`、
依存素材なども変更するなら対象に含めます。未保存の状態、指定外への変更、機器や通信の
副作用は復元対象になりません。Undo や Python の Private 実行スコープを完全な復元・隔離と
みなさないでください。エラーでも途中の変更は残り得ます。結果を読んでから修正します。

出力と例外は各最大約 32,768 文字までモデルへの結果・JSON に保存します。
UE 自体の Python 出力・例外は UE のログにも入るため、秘密や個人情報を出力しないでください。
画面キャプチャと PIE の既存ツールは従来の確認を維持します。ただし、任意 Python は
同様の操作も可能なので、制作モード全体にその制限が強制されるとは扱いません。

## 復元

プラグインに同梱した `Scripts/Restore-PythonRun.ps1` を PowerShell から使います。
最初は変更予定だけを表示します。

```powershell
./Scripts/Restore-PythonRun.ps1 -ProjectRoot 'C:/path/to/UnrealProject' -RunId '<実行ID>'
```

UE Editor を終了し、同じコマンドに `-Apply` を付けると復元します。
既存ファイルをバックアップの内容へ戻し、その実行で新規作成されたと記録されたファイルを
退避します。復元直前のファイルも `before-restore/<復元ID>/` に保存して照合するため、
後から行った編集も捨てません。元のバックアップのハッシュも検証します。

Editor が異常終了して `running` のままなら、完了後の新規ファイル一覧はありません。
その場合は変更前バックアップを戻せますが、未記録の新規ファイルは別に確認が必要です。

## 再利用

納得できた実行を `ue_python_save_recipe` で保存し、`Scripts/CinderLink` のコードを Git で管理します。
実行記録やバックアップの `Saved` はローカル保管用です。素材も Git 管理外なら別途保管します。
この保存機能はコードのコピーであり、初期状態からの再現性を自動保証するものではありません。
採用前に、素材の依存関係と再実行時の挙動も確認してください。
